# 代码渲染的音乐 MV

给一首歌做动画 MV：每一帧都是代码画的，浏览器逐帧渲染，ffmpeg 配上原曲。分工是固定的：用户定方向、看样片、按时间点挑错；你写全部代码、自己检查画面，交付成片。

这套做法来自 2026 年 9–10 月用 Claude Opus 5.5（Claude Code，推理强度开到最高）做的八支片子，每支一种画风。一支全曲 MV 约一个工作日加两三轮修改，短片 6–9 小时；按 API 价格折合 130–360 美元一支，大头是并行的子代理和人物设计。管线每次都一样，难的是画风和人物：被否掉的方案几乎都栽在这两处。

## 先记住的规则

1. **每一帧只由时间 t 决定。** 页面的 `renderAt(t)` 是纯函数：不用 `Math.random`、`Date.now`、`performance.now`、`THREE.Clock`，帧与帧之间不留状态。这样才能多进程乱序渲染、中断续渲、改哪个镜头只重渲哪一段。这条规则不检查就会被悄悄破坏（一支验收了九版的片子里有两帧是别的画面），所以交付前多进程正着、单进程倒着各渲一遍，逐字节比对（`render.mjs --compare`）。模拟类画面（流体、布料）每个镜头从固定的预滚开始算。
2. **歌词只当数据，不进任何模型输出。** 回复、推理、文件内容、命令、子代理任务书里出现歌词原文，整条回复会被输出端的版权过滤拦掉（一天里发生过七次，换说法也没用，推理里提到一句就够）。歌词由脚本下载、脚本处理，脚本只打印时间和字数；提到某句时说“第 12 行”或转述意思；画面里的字由页面从 `lyrics.json` 读。
3. **你看不了播放。** 只能看图和测量：联系表看整体，逐帧条看卡点，原尺寸局部看手脚和接触，每张图都要真的打开看。节奏手感、卡点对不对味、闪光的强弱只有用户能判断；交付时把这些点明说出来。
4. **先试片定画风，再铺开。** 两三个方向在同一段音乐（10–16 秒，含全曲最重要的那一下）上并行各做一支，附人物定妆表，你先审过再给用户挑。画风和人物都签字之后，才开子代理并行做整片：并行开始后才发现人物不对，要返工好几章。
5. **第一帧就是一幅完整的画。** 刷到时第一帧就是缩略图，不能是黑场或空画面，歌开头是静音也一样。横竖屏由内容决定，不按上一支的习惯。
6. **人物是最大的风险。** 用户会一件一件地看衣服和身体。人物要好看，而且属于这首歌的那一类片子（青春校园、都市、热血番……）；人物撑不住时可以用画风藏（剪影、小像素、Q 版、背影、皮影），但要先问。每个姿势在原尺寸下查手、脚、胯、脖子和图层顺序（`references/characters.md`）。
7. **3D 人物直接渲染会像游戏画面或塑料玩具。** 三次被否：塑料感的鸟、像游戏过场的悟空、需要修的地方太多的 3D 房间。3D 擅长环境、光和成群的东西；人物要么做 2D，要么拿 3D 当底稿再画成 2D。
8. **验收即冻结。** 用户说可以之后，只做被要求的那件事。发现问题先说一句并给出办法，不要顺手改已经验收的片子。
9. **素材有来路。** 音频由用户提供，必须是和歌词时间轴对得上的版本（通常是专辑原版）；从视频平台下载要用户明确同意。模型、字体、贴图的来源和许可记下来，写进 README。

## 流程

每一步做完先给用户看，再进下一步。用户说“做完你先自己检查，我明早再看”时，就自己走到底，交付时附上版本表和要看的点。

| 步骤 | 做什么 | 交给用户的 | 详见 |
|---|---|---|---|
| 0 开工 | 建项目目录；确认音频版本、全曲还是一段、截止时间 | 一句话确认 | 下文“工具” |
| 1 量歌 | 量速度、小节、段落和重音；取逐字歌词并对时间 | 歌曲结构表 | `references/song.md` |
| 2 方向 | 读懂这首歌，提两三个方向，推荐一个 | 方向说明 | `references/direction.md`、`references/styles.md` |
| 3 试片 | 每个方向一支试片加定妆表，开分支并行 | 并排对比图、几支试片 | `references/direction.md` |
| 4 人物 | 人物包和定妆表 | 定妆表，签字 | `references/characters.md` |
| 5 分镜 | 镜头表、连续性表、接缝表、节拍表 | 分镜 | `references/production.md` |
| 6 引擎 | 从选中的试片长出整片引擎，做一个范例镜头，写说明 | — | `references/pipeline.md` |
| 7 并行 | 子代理按连续动作分镜头，各改各的文件 | — | `references/production.md` |
| 8 总装 | 全片一览、接缝、卡点、确定性、帧检查，合成 v1 | v1 和要看的点 | `references/review.md` |
| 9 修改 | 按用户的时间点改，每版另存 | v2、v3… | `references/production.md` |
| 10 终检 | 颗粒、色彩范围、音画偏移、帧间突变 | 成片 | `references/review.md` |
| 11 收尾 | 先重建验证再删帧，写 README，把新经验补进这个 skill | README | `references/wrapup.md` |

**0 开工。** `python3 <skill>/scripts/new_project.py <歌名拼音> --w=1920 --h=1080 --fps=30 --title="歌名 · 歌手"`，进目录 `npm install`。需要 Node 18+、Python 3（numpy、scipy、Pillow）、ffmpeg 和 Chrome。用户把音频放进 `assets/`。一次问清：全曲还是一段（全曲的用时和花费是短片的两三倍）；有没有想要的感觉或参考；什么时候要。横竖可以等方向定了再按内容定。

**1 量歌。** `python3 -I tools/analyze_audio.py --plot=out/check/audio.png`，读速度候选（最高分的可能是半速）、偏离网格的程度、两小节一行的响度表。`tools/fetch_lyrics.py --keyword "歌手 - 歌名"` 取酷狗的逐字歌词，`tools/build_lyrics.py` 合并、对到人声上，读它打印的偏移候选。整理成结构表：段落、时间、相对响度、全曲最重的一下、音乐收薄和停顿的地方。只做一段时，`tools/make_timing.py` 会提示切点上有没有上一句的尾音。

**2 方向。** 先回答：关键那句在歌里是什么意思；音乐真正的高潮在哪（量出来的，不一定是最有名的那句）；什么东西能贯穿全片讲两个人的关系。每个方向写清画风、一句话故事、为什么这个画风能演这首歌、横竖、会被拿去和什么比、最大的风险。画风从 `references/styles.md` 的目录里挑或组合。

**3 试片。** 用 `tools/make_timing.py --clip=a:b --out=look_tests/clip.json` 定片段，每个方向一个分支（带着全部上下文的 fork），任务书用 `assets/docs/BRIEF.md` 的 A 节。第一轮的试片几乎都有问题（太挤、人物太小、像模型），返工一两轮再给用户。用户常挑一个组合，而不是你的排序。

**4 人物。** 先定人物属于哪一类片子，再设计；做成独立的人物包（接口加文档），写镜头的人只调用不修改。定妆表包括全身、近景、站走坐和关键动作、片中实际大小、缩到 320 宽的缩略图。

**5 分镜。** 模板 `assets/docs/STORYBOARD.md`：每个镜头写读点（观众要按顺序看懂的事，各带时间）、卡点、转场；连续性表（信物、天色、灯、站位）；接缝表（每处交界两边必须一样的画面）。把镜头写进 `tools/make_timing.py` 的 `SHOTS`，生成 `assets/timing.json`；还没写的镜头会画成带名字的占位卡，整片从第一天起就能按正确时间渲出来。

**6 引擎。** 从选中的试片长出整片引擎，不另起炉灶。骨架是 Canvas 2D 的；画风要 three.js、自写 WebGL2 或 p5.js 时照样遵守页面约定（`references/pipeline.md`），在 `renderAt(t)` 里画到 `#stage`，`render.mjs` 和所有检查照常可用。共用部分先做对：渲染器、人物、布景、字幕、设定图；然后写完一个范例镜头，再写 `docs/GUIDE.md`（模板 `assets/docs/GUIDE.md`，最有用的是逐行讲解的范例镜头、踩过的坑和引擎做不到的事）。子代理会照抄模板，模板里的错会被抄进好几章。

**7 并行。** 按连续动作分工（一段连续动作给一个人，写成一个时间的函数，几镜共用），不按时长平均分：短片三个子代理，全曲五到七个，每人 45–75 分钟。任务书用 `assets/docs/BRIEF.md` 的 B 节。每人只改自己的文件；共用代码的问题由你统一修，修完通知大家去掉各自的临时补丁。他们交上来的图你自己打开看。

**8–10 总装、修改、终检。** 每个镜头都合格，整片不一定成立：先看全片一览，再看每个接缝、每个重拍、每处原尺寸局部。用户的意见按时间点来；时间点和画面对不上时先说出你的理解。改肢体之前先发改前改后的静帧给用户确认。每一版另存文件名，README 里记版本表。终检的检查项在 `references/review.md`。

**11 收尾。** 先从干净状态重建一遍、和成片比对，再删渲染帧；README 按 `assets/docs/README.md` 写，审片清单里记下用户指出的每一处和以后要查什么。最后把这支片子的新画风（附一张样图）和新教训补进这个 skill 的 `references/styles.md` 和 `references/review.md`。

## 工具

都在 `scripts/` 里；`new_project.py` 把它们复制进项目（`render.mjs` 放根目录，其余放 `tools/`），项目自带副本，以后 skill 变了也能按原样重建。在项目根目录运行。

| 脚本 | 做什么 |
|---|---|
| `new_project.py` | 建项目：页面骨架（`index.html`、`src/main.js` 页面约定、`lib.js`、逐字字幕 `caption.js`、示例和占位镜头）、工具、文档模板 |
| `render.mjs` | 驱动页面：预览、单帧、联系表、逐帧条、原尺寸局部、全片一览、帧序列（多进程、倒序）、合成 mp4、逐字节比对、在页面里求值 |
| `analyze_audio.py` | 速度、小节线、逐帧响度和人声等曲线、重音；`--track` 给相位会漂的歌 |
| `fetch_lyrics.py` | 酷狗逐字 KRC、网易云 lrc/yrc、LRCLIB；只打印数字 |
| `build_lyrics.py` | 合并几份逐字歌词，对到人声起音上，写 `assets/lyrics/lyrics.json` |
| `make_timing.py`（项目模板） | 片子范围、镜头、小节线、重音、歌词行 → `assets/timing.json`；`--clip` 给试片 |
| `cut_vocal_tail.py` | 从一段的开头减掉上一句的尾音（用分离出的人声） |
| `check_frames.py` | 平均亮度、黑帧、切点以外的突变、冻住的段落、两次渲染的像素差、颗粒是不是网格 |
| `check_no_lyrics.py` | 扫描文档和代码里有没有混进歌词原文，只报文件和行号 |

常用命令（时间都是原曲的秒数）：

```bash
node render.mjs --serve                                         # 预览页：拖时间条，空格播放
node render.mjs --list                                          # 镜头和帧范围
node render.mjs --sheet=84.7:97:0.5 --cols=6 --w=320 --out=out/check/a.jpg      # 联系表
node render.mjs --shot=s04 --sheet --n=12 --out=out/check/s04.jpg               # 一个镜头的 12 帧
node render.mjs --strip=95.45:95.7 --cols=8 --w=240 --out=out/check/b.jpg       # 一刻的每一帧（卡点）
node render.mjs --sheet=95.6 --crop=700,300,500,400 --w=1000 --out=out/check/c.jpg   # 原尺寸局部
node render.mjs --film-sheet --n=48 --out=out/check/film.jpg                    # 全片一览
node render.mjs --frames --workers=3 && node render.mjs --encode --out=out/<名字>_v1.mp4
node render.mjs --frames --shots=s04 --workers=3 --tag=a && node render.mjs --frames --shots=s04 --reverse --tag=b && node render.mjs --compare=a,b
node render.mjs --eval="CAPTION_TABLE()"                        # 每行字幕的进出时间
```

## 参考文件

读到哪一步，就读哪一份；不用一次读完。

- `references/song.md`：音频来源、量歌、读结构、歌词只当数据、取歌词和对时间、和声、字幕设计、截片段和尾音、人声分离。
- `references/direction.md`：从歌到片的构思、范围和横竖、第一帧、节奏和镜头、热血和同人、提方向、试片、被否掉的方案。
- `references/styles.md`：画风目录（八支成片各附样图和视频链接，另有十几种试过或提过的画风）、怎么选画风。
- `references/characters.md`：人物的类型和好看、几种做人物的办法、定妆表、剪影、Q 版、现成 3D 模型、解剖和图层清单。
- `references/production.md`：分镜、节拍表、共用部分、写给子代理的说明、并行、总装、修改轮、通宵模式。
- `references/pipeline.md`：项目目录、页面约定、`timing.json`、`render.mjs`、确定性、渲染器和速度、合成和色彩、颗粒和发光、局部重渲。
- `references/review.md`：自查三件套、测量、交付前清单、终检、八支片子的审片清单。
- `references/wrapup.md`：验收之后、素材和许可、收尾整理。
- `assets/docs/`：分镜、写镜头说明、任务书、项目 README 的模板。`assets/project/`：页面骨架。`assets/styles/`：八支片子的样图。
