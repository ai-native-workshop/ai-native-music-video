## 验收之后

- 用户说可以之后，片子（连同第一帧）冻结。用户说“开始发布”时，问清或判断清要的是什么（标题简介、封面，还是都要），先做被要求的那件。《悟空》验收后，用户要的是标题和简介，助手却先去改了已经验收的封面版式、重新合成了片子，被用户叫停（“封面不用改，我意思是发布视频的时候的标题和简介”），只好全部还原。
- 验收后发现的问题：一句话告诉用户，给一个绕过的办法（例：上传时另选封面图），不自己动片子。用户之后要了，再另外做，片子保持逐字节不变。

## 封面

| 平台 | 比例 | 尺寸 |
|---|---|---|
| 抖音 | 9:16 | 1080×1920 |
| 抖音主页格子 | 3:4 | 1080×1440 |
| B 站 | 16:9 | 1920×1080 |
| B 站 | 4:3 | 1440×1080 |

（B 站也可以给 16:10。）每张一版带字、一版不带字（`_clean`）；常做两个画面（主推和备选），共 16 张。

- **选哪一帧**：首选全片最有画面的那一帧，通常是用户第一次说“很有画面感”的那一下（《人质》红色绽开的那一帧，主推的花窗反而没被选）。每张候选都带歌名和歌手。
- **字**：用片子里的字（竖排宋体、像素字、片子的标题卡），用人物的颜色，放在画面最亮的空处，不加描边和色块。
- **竖封面的安全区**：片名和人物在中间 3:4 以内（主页格子从中间裁），在底部 18% 以上（被界面盖住）。
- **按目标尺寸重新渲染再裁**，不要把帧放大：竖片的帧裁成横的只有 1080 宽。给页面加一个封面模式：相机由参数给出，关掉所有画在画面坐标里的层（暗角、颗粒、字幕、左栏），片名和公式放在场景坐标里。
- **比页面能渲的更高的封面**（横片要竖封面）：分成几块重叠的拼块渲染再接起来。辉光会伸出内容约 70 像素，每块只用离边 150 像素以内的行，重叠带用 80 像素的软过渡；比较重叠带两边的像素，就能发现接缝。
- **像素片**：用原生像素重新取景，竖版上下不够的行由画面边缘的行往外延续、逐渐变暗，再按整数倍放大。
- 封面另外渲染，不动片子；封面脚本写清每张的参数，能重做。

## 标题和简介

写成纯文本（不用 markdown），存进 `docs/POST.txt`，回复里也贴一份，方便用户在别的设备复制。模板 `assets/docs/POST.tpl`。

- **短视频**（几十秒）：标题一行，一个推荐加两三个备选；简介三行以内：发生了什么、怎么做的、署名一行。抖音再精简成一句加话题标签。用户原话：“短视频文案不宜太长，用户一般不会看那么多”。
- **全曲 MV**：先讲故事（三行左右），再讲片子用什么讲这首歌，然后分段导览（时间 + 一句），制作说明，署名；另备一版 1000 字符以内，一版极短的。
- **标题引用歌词**（前几支片子的标题格式：“一句歌词” ——《歌名》画风 MV）：模板里写 `{{L12}}`，`python3 -I tools/fill_post.py` 从歌词数据填进去；回复里只给占位符版本，说文件里已经填好。不要自己写出那一句。
- **制作那一行**，每次都用：没有用生图或生视频模型，每一帧都是代码画的；代码由 Claude Opus 5.5 编写，我负责定方向和逐帧挑错。用了现成素材（游戏模型）要写明。
- **署名**：演唱、词、曲、编曲，专辑和年份；“非官方 MV，自制动画。音乐版权归原权利人所有。”
- 文案里的数字从程序里读出来核实。
- **B 站简介里不要放任何站外网址**（GitHub、网页版）：会被判“违规推广内容”退回。链接放在置顶评论，画面里写“入口见评论区”。
- 用了视频生成模型的镜头要在简介里标注（这套做法不用）。

## “求提示词”

在 Opus 代码视频这股风潮里，评论区的“求提示词”指的是创作者开场时给 Claude 的那段话。回复分三块：
1. 短回复（创作者的口吻）：不是一句提示词出的片，是在 Claude Code 里跟 Claude 商量着做的：我说想法、看样片、定方向、逐帧挑错，前后一天，改了几轮。
2. 精简开工说明：一条评论放得下（约 700 字），连在回复后面。
3. 完整开工说明（`docs/PROMPT.txt`），评论放不下就发动态或私信：
   - 准备：装好 Node.js、Python 3、ffmpeg、Chrome；专辑原版音频放进空文件夹；在这个文件夹里开 Claude Code；用的模型和推理强度；大致用量（一支全曲折合三百多美元，建议先只做 16 秒试片）。
   - 目标、画风、人物、故事（按段落，带大致时间）、歌词和节拍（歌词只当数据）、技术路线、流程（每一步先给我看）、做过一遍才知道的坑、交付前逐项查。换一首歌时只换故事。
   - 全文不写歌词。
- 现在也可以直接指向这个 skill 的仓库（B 站简介里不放网址，放评论）。

## 版权和平台

- 音乐是原曲：按非官方的自制动画发布，平台可能限流或下架。抖音 2020 年起有杰威尔全部歌曲的短视频片段授权；整首在 B 站会不会被处理，没查到明确说法。
- 歌词是受版权保护的文字：不出现在模型输出、文档、代码和公开的仓库里，画面里的字从数据画。
- 素材：游戏里提取的 3D 模型，上传者没有授权的资格（即便标了 CC-BY）；CC-BY 的素材要署名；用过来源不明的示例头像的试片不要公开；字体用 OFL 的，许可证放进项目。
- 在国外网络环境下访问 B 站会被当作海外用户，部分接口返回 412；查稿件状态可以用公开的稿件简介接口或浏览器打开页面。

## 收尾整理

用户说“已发布，总结并清理项目文件夹”时：

1. **先验证再删。** 记下要保留的帧的哈希，把帧挪开，用 README 里记录的命令从源码重建到另一个文件名，比对帧和 mp4。成片之后改过的代码（为封面加的开关、改过的衔接）是重点。《人质》重建出的 mp4 和成片 SHA-256 相同；《悟空》有两帧不同，于是发现了冲击帧的问题。重建出来不一样时，再渲一次确认，再下结论（《万有引力》有一张封面拼块一次不同，再渲又一样了）。
2. **去掉陷阱。** 重建脚本不默认写成片的文件名；会读取被删文件的脚本，缺了要能自己补出来；每条记录的命令在清理后的目录里跑一遍。
3. **试片。** 从保留的源码重渲、比对，再删它们的帧；记下当时用的画质开关。
4. **保留**：成片和小副本、封面、试片 mp4、源码、assets、node_modules、文案，以及 `docs/img/` 里十张左右的记录图（试片并排、定妆表、用户要求修改的改前改后、全片一览）。**删除**：渲染帧、检查图、中间版本（移到废纸篓可以恢复）、不再被渲染的下载物（记下来源）。报告里说清什么是永久删了的。
5. **README**：模板 `assets/docs/README.md`：是什么、怎么做的、目录、分镜、制作流程和版本表、命令和开关、封面、规模、经验（按主题）、审片清单、已知的不足。事实从数据来：歌曲结构从歌词时间，时间线从文件修改时间和消息时间戳（会话记录里的时间是 UTC）。
6. 分镜和写给子代理的说明按成片更新，不要留着“还没做”的字样。
7. `python3 -I tools/check_no_lyrics.py`：文档里没有歌词原文。
8. **规模和费用**：帧数、每帧毫秒数、全片渲染时间、代码行数、小时数；token 和折合费用从会话记录里统计：Claude Code 的会话记录在 `~/.claude/projects/<项目>/<会话>.jsonl`，子代理的在 `<会话>/subagents/`；每条 assistant 消息带 usage（按 message.id 去重）。按 API 价格折算时注明单价。往期参考：全曲 250–360 美元，短片 130–240 美元；98% 的 token 是重读上下文；约七成花在并行的子代理上；检查图占发送 token 的 14–22%。
9. **把这支片子的经验补进这个 skill**：新画风写进 `references/styles.md`，用户指出的问题加进 `references/review.md` 的审片清单，新坑写进对应的参考文件。
