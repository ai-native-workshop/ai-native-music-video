# 验收之后和收尾

## 目录
- 验收之后
- 素材和许可
- 收尾整理

## 验收之后

- 用户说可以之后，片子（连同第一帧）冻结，只做用户接着要的那件事。有一次验收后用户要的是另一样东西，助手却先去改了已经验收的画面版式、重新合成了片子，被用户叫停，只好全部还原。
- 验收后自己发现的问题：一句话告诉用户，给一个绕过的办法，不自己动片子。用户要改，再改；要另做的东西（比如换个比例的画面）另外渲染，片子保持逐字节不变。

## 素材和许可

- 歌词是受版权保护的文字：不出现在模型输出、文档、代码和任何要分享的东西里，画面里的字从数据画。分享项目文件之前跑 `tools/check_no_lyrics.py`。
- 音频由用户提供；记下来源。
- 游戏里提取的 3D 模型，上传者没有授权的资格（即便标了 CC-BY）；CC-BY 的素材要署名；来源不明的示例头像只用在不公开的试片里；字体用 OFL 的，许可证放进项目。每样素材的来源和许可写进 README。

## 收尾整理

用户说“总结并清理项目文件夹”时：

1. **先验证再删。** 记下要保留的帧的哈希，把帧挪开，用 README 里记录的命令从源码重建到另一个文件名，比对帧和 mp4。成片之后改过的代码（后来加的开关、改过的衔接）是重点。《人质》重建出的 mp4 和成片 SHA-256 相同；《悟空》有两帧不同，于是发现了冲击帧的问题。重建出来不一样时，再渲一次确认，再下结论（《万有引力》有一次一块画面单次不同，再渲又一样了）。
2. **去掉陷阱。** 重建脚本和其他生成脚本都不默认写到交付过的文件上；会读取被删文件的脚本，缺了要能自己补出来；一个文件夹里有两版片子时，各用各的数据文件，默认渲交付的那一版（《于是》被否的 3D 版的时间表工具写的是像素版也在用的 `timing.json`，`render.mjs` 不加参数渲的也是 3D 版）；每条记录的命令在清理后的目录里跑一遍。
3. **试片。** 从保留的源码重渲、比对，再删它们的帧；记下当时用的画质开关。
4. **保留**：成片和小副本、试片 mp4、源码、assets、node_modules，以及 `docs/img/` 里十张左右的记录图（试片并排、定妆表、用户要求修改的改前改后、全片一览）。记录图按最终的代码重渲，和旧的比一下：中途某一轮渲的定妆表、全片一览会比成片旧（《于是》的定妆表上还是旧的领口和背影的胳膊，全片一览里还是旧的手）。改前改后的图在旧版本移走之前从旧 mp4 里截；哪一版没留下来就注明。**删除**：渲染帧、检查图、中间版本（移到废纸篓里带日期的文件夹 `~/.Trash/<项目>_superseded_<日期>/`，可以恢复，也不会重名）、不再被渲染的下载物（记下来源）。报告里说清什么是永久删了的。
5. **README**：模板 `assets/docs/README.md`：是什么、怎么做的、目录、分镜、制作流程和版本表、命令和开关、规模、经验（按主题）、审片清单、已知的不足。事实从数据来：歌曲结构从歌词时间，时间线从文件修改时间和消息时间戳（会话记录里的时间是 UTC），文件名从 `out/` 的列表（交出去的文件可能被用户改了名）。
6. 分镜和写给子代理的说明按成片更新，不要留着“还没做”的字样。
7. `python3 -I tools/check_no_lyrics.py`：文档和代码里没有歌词原文。默认按连续 6 个字算；收尾时再加 `--min=4` 扫一遍：《于是》这样又找出两处和歌词相同的短语（一个镜头标签，也进了生成的 JSON；一格分镜），默认扫描对那个标签报 0 条。改写措辞，重新生成用到它的数据。4 个字也会命中常见词和四个字以上的歌名，逐条看。
8. **规模和费用**：帧数、每帧毫秒数、全片渲染时间、代码行数、小时数；token 和折合费用从会话记录里统计：Claude Code 的会话记录在 `~/.claude/projects/<项目>/<会话>.jsonl`，子代理的在 `<会话>/subagents/`；每条 assistant 消息带 usage（按 message.id 去重）。按 API 价格折算时注明单价。往期参考：全曲 250–360 美元，短片 130–240 美元；98% 的 token 是重读上下文；约七成花在并行的子代理上；检查图占发送 token 的 14–22%。
9. **把这支片子的经验补进这个 skill**：新画风写进 `references/styles.md`（附一张样图放进 `assets/styles/`），用户指出的问题加进 `references/review.md` 的审片清单，新坑写进对应的参考文件。
