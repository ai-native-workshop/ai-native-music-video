# 《歌名》· 写镜头的说明

> 给并行写镜头的子代理看。引擎作者在做完一个范例镜头之后写这份；引擎改了就同步改这里。片子做完后保留，当作引擎的接口文档。

你在给《歌名》写镜头。页面 `index.html` 能画出任意一秒，`render.mjs` 在无头 Chrome 里逐帧渲染它。先按顺序读：这份说明、`docs/STORYBOARD.md`（尤其你的那几镜）、`assets/timing.json`（镜头时间、重拍、歌词行）、范例镜头 `src/shots/sNN.js`。

## 规矩

1. **只改自己的文件**：`src/shots/<你的镜头>.js`，私有零件放 `src/shots/_<镜头>_*.js`。引擎、人物包、别人的镜头都不改。缺什么就在自己文件里私下写一份，并在报告里说；发现共用代码的 bug 也一样：在自己文件里绕过，报告里写清楚，由统筹统一修。
2. **每一帧只由 t 决定**：不用 `Math.random`、`Date`、`performance.now`；模块变量不在 `draw` 里改；随机数用 `K.rng(seed)` 或 `K.L.hash(i)`。
3. **不写歌词原文**：代码、注释、命令、报告、你自己的推理里都不写。提到某句用行号。字幕由引擎画。
4. 检查图放 `out/check/<镜头>/`，临时脚本的文件名带上镜头号：几个代理共用一个临时目录，会互相覆盖。
5. 渲帧、合成这类长命令放后台跑。

## 命令（在项目根目录跑）

```
node render.mjs --shot=s04 --sheet --n=12 --cols=6 --w=320 --out=out/check/s04/sheet.jpg     一个镜头的 12 帧
node render.mjs --strip=95.45:95.7 --cols=8 --w=240 --out=out/check/s04/strip.jpg            重拍前后的每一帧
node render.mjs --sheet=95.6 --crop=700,300,500,400 --w=1000 --out=out/check/s04/crop.jpg    原尺寸局部
node render.mjs --frames --shots=s04 --tag=a && node render.mjs --frames --shots=s04 --tag=b --reverse && node render.mjs --compare=a,b
```

## 交付前自查

1. 每个镜头 12–18 帧的联系表；每个重拍前后的逐帧条：动作落在重拍之后的第一帧，不晚一帧。
2. 手、脚、胯、脖子、接触处的原尺寸局部；缩到缩略图大小看轮廓读不读得出来。
3. 每个镜头的第一帧和最后一帧都是完整的画；和相邻镜头的接缝并排看。
4. 有字幕的时候，脸和关键动作不在字幕区里。
5. 确定性：自己的镜头正着、倒着各渲一遍，`--compare` 逐字节相同，然后删掉这两组帧。
6. 报告：每个镜头逐拍写发生了什么（带时间）；检查了什么；弱点；ms/帧；联系表和逐帧条的路径；偏离分镜的地方和理由；绕过的共用代码问题。
